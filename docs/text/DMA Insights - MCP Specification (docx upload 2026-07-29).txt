0.2 Session continuity — how to resume cold
A new session should read, in this order: §1 for the shape, §3 for the identifiers, §5 for what it owes, §6 for the lifecycle. That is enough to start producing. §13 is the checklist to run before claiming anything is finished.
Three things a resuming session must never assume:
That an identifier can be invented. Every id in §3 has exactly one authority, and for most of them the authority is not the producing agent.
That a partially-promoted run is a valid state. It is not — see §6.5.
That a surface renders because the payload was accepted. Accepted means staged; rendered means promoted. They are different states and §6 keeps them apart.
1. What the MCP is, and where it sits
The MCP is the only writable boundary into the application's content. It exists so that a producing agent — which reasons, searches, enriches and writes prose — can hand finished, validated content to an application that does none of those things at request time.

1.1 The four hard boundaries
Boundary
Rule
The agent never writes a serving table
All writes go through the MCP. There is no side door, no direct SQL, no admin bypass. A surface that appears without a promotion is a bug in the MCP, not a shortcut that worked.
The app never calls a model
Request-time rendering is pure reads. Every sentence an AE sees was produced ahead of time, validated, and persisted. This is what makes the app fast, cheap and reproducible — and what makes a hallucination a build-time failure rather than a runtime surprise.
Staged is not served
A submission that passes validation is STAGED. It renders only after promotion. The two states exist so a run can be assembled surface by surface without a client ever seeing a half-built page.
The contract is served, not remembered
get_page_contract returns the field shapes AND their spec text. A producing agent should read the contract at the start of every run rather than rely on a remembered shape, because a remembered shape that still type-checks promotes silently wrong content.

3.3 Evidence ids in detail
Evidence is where identifier discipline actually gets tested, because it is the only class where the agent brings something new to the system.
Two legal origins
PACKAGE. E-nnn, already in the evidence store with an entity, a run, a tier and a URL. Cite it; never create it.
MINT. Anything found outside the package is REGISTERED first and cited second. register_evidence returns the id. The server allocates E-CC-nnn sequentially within the run.
One recogniser, four namespaces
The retired system had five different regexes for this, with three different digit bounds, and not one matched the mint namespace it was supposed to be checking. Since every one of them used its pattern to diff claimed ids against an allowed set and flag the remainder, a pattern that could not SEE an id could not flag it — so genuine mints passed unchecked and fabricated mints were equally invisible.
EID_TOKEN_RE = \b(?:E|EV|INT)-[A-Z0-9]+(?:-[A-Z0-9]+){0,3}(?![A-Za-z0-9-])

  matches      E-047   E-7   E-1234   E-CC-001   EV-P2C4-013   INT-DISCOVERY-04
  rejects      e-047 (case)   E-047abc (partial)   PRE-047   P1C1.1.1   REC-04

Properties that are load-bearing, not stylistic:
  case-SENSITIVE   lowercasing makes every "e-" in prose a candidate
  no partial match the trailing (?![A-Za-z0-9-]) stops a match ending
                   mid-token, where \b would allow it
  order preserved  the truncated-cell recovery path takes the FIRST token,
                   because in a comma-joined cell only the last one is cut

ONE recogniser, in one module, imported everywhere. A private copy in a second module is how the hole re-opens, so a test asserts identity of the compiled object at every call site.

The canonical rendering
inline, in prose      [E-047]           or  [E-047, E-089]
in arrays             "e_ids": ["E-047", "E-089"]        ← bare, no brackets

The brackets belong to the CHIP, not to the id. The frontend renders a bracketed
group as a click-through control; a bare id inside prose renders as literal text
and is a defect.

3.4 Grain — the single most expensive mistake
A quoted figure and the cell id it names must be the SAME cell. In the retired system one line paired a sub-capability's score with a category's id and produced 125 gate violations; it fell to 40, then 8, then 1 as each layer was fixed and re-measured. Nothing was accommodated by loosening the gate.
WRONG   "Data Warehouse & Data Lake ... at 1.6/5"     ← the name of a subcap
                                                        with the CATEGORY's mean

RIGHT   subcap_id = P4C1.2.1
        name      = "Data Warehouse & Data Lake"
        score     = 1.6          ← both read from the SAME row

ASSERTION at submit: for every "<label> at N/5" in produced prose, resolve the
label to a served cell and require |rendered - served| <= 0.05.

Grain is asserted at submit, not reviewed later. A grain mismatch fails the submission while the agent can still repair it.

Two rules that were repeatedly broken and cost real score accuracy:
A machine technographic scan is T1, never T4. Filing it as T4 caps the capability at L2.5 and silently suppresses the score. It was the most common misclassification in the retired corpus.
There is NO T6, T7 or T8 in the quality ladder. The retired frontend carried a separate 8-row SOURCE-TYPE display table that collided with this one on rows 4 and 5 — so an item filed T4 (internal unvalidated) rendered to an AE as “Marketing claim”, and one filed T5 (marketing, weakest, needs corroboration) rendered as “Analyst inference”, which reads STRONGER than it is. The new app renders the quality tier and its label from ONE table.
ERS — Evidence Rank Score, 1.0 to 5.0
ERS = (0.35 × Tier) + (0.25 × Recency) + (0.20 × Specificity)
                    + (0.20 × Corroboration)

EVERY factor is itself scored 1.0–5.0, so ERS is bounded 1.0–5.0.
      High >= 3.5      Medium 2.5–3.5      Low < 2.5

Factor 5.0 / 4.0 / 3.0 / 2.0 / 1.0
  Tier           T1 / T2 / T3 / T4 / T5
  Recency        CURRENT / RECENT / DATED / STALE / ARCHIVAL   (bands below)
  Specificity    quantified+method / quantified / specific-qualitative /
                 general / vague
  Corroboration  3+ independent / 2 independent / single T1-T2 / single T3 /
                 single T4-T5

"Independent" = different ORIGINS. An annual report and an investor deck from
the same institution are ONE source: corroboration 3.0, not 4.0.

ERS is computed by the SERVER at register_evidence, never sent by the agent. It can never be below 1.0 — assert 1.0 <= ers <= 5.0 on ingest and quarantine anything outside the range. The retired app rendered “ERS 0.78”, which is below its own floor.

→  { "run_id": "<uuid>", "e_ids": ["E-047", "E-CC-003"] }

The three-way split is the point. not_found means fabricated or not yet registered. FOREIGN is the dangerous one — a real row belonging to another institution — and it must stop production rather than be filtered out quietly, because its presence means the reasoning has drifted onto the wrong entity.

5.2 Two placement rules
A section goes on the page whose PRODUCING CONTEXT already determines it. An agent filling cell_evidence is reading the workbook cell by cell, so workbook_scores, the alerts that are its complement, and the evidence-age tracker all belong on the same page and come out of one reading.

6. The lifecycle
  claim ──▶ produce ──▶ [register_evidence]* ──▶ submit ──▶ verdict

                                            fail ◀──┘          │ pass

6.1 Claim
A run is claimed before production so two sessions cannot produce the same run concurrently. list_pending_runs shows what is unclaimed; the claim carries a lease with an expiry so a dead session does not block a run forever.
6.2 Produce
The agent's work, governed by the Surface Design Specification. Read the bundle, read the contract, read the catalogue, reason, enrich, challenge, cite, write.
6.3 Submit and the verdict
Validation runs in two passes, deliberately separated:
STRUCTURAL AND EDITORIAL: required fields, types, grain resolution, word budgets, forbidden registers (no internal codes in client prose, no score-predicate openers, no toolkit diagnostic questions), terminal punctuation, id resolution.
EVIDENCE: every cited id resolves, belongs to this entity and this run; every excerpt is verbatim in the artifact where the app holds it; every source domain passes the identity check. This is database work of a different shape from the format sweeps, which is why it is its own pass.
ANY evidence reason fails the submission. An excerpt is either a copy of something a document says or it is not evidence. The check lives at submit rather than promote so the agent can still repair the span.

6.4 Supersession
A resubmission for the same (run, page) SUPERSEDES the previous row. Submissions do not accumulate, there is no merge, and the last passing submission is the one that promotes. This makes iteration safe: an agent can submit, read the verdict, repair and resubmit without cleaning up after itself.
6.5 Promotion is all-or-nothing
promote_run requires a PASS row for EVERY page. There is no partial promote, so a client is never looking at a page from the new run beside a page from the old one.

On success, each page's writer runs into the serving tables inside one transaction and the staging rows are marked promoted. On failure, 409 with missing_pages and unpassed_pages — nothing is written.
6.6 Reruns and invalidation
A new run for an entity does not delete the old one. Promotion swaps which run is ACTIVE, and the previous run stays queryable for the longitudinal surfaces (velocity, recurring themes, seen-in-N-runs). Anything derived from the superseded run is invalidated lazily, and a catalogue version bump invalidates by version tag so renamed cells resolve through the alias bridge rather than silently vanishing.

7.1 The safeguard gates are client-visible — write them accordingly
This family is unusual and was mishandled in the retired system: its results render on a client-facing surface. Three consequences.
PLAIN LANGUAGE. “SG-04 Evidence per cell” with a human sentence beside it, never a bare code. A client reading “G04 FAIL” learns nothing and distrusts everything.
HONEST BY CONSTRUCTION. A gate that reports PASS because it did not run is worse than one that reports FAIL. Emit a third state — NOT_RUN, with the reason — rather than defaulting to PASS.
A FAILING GATE IS NOT A BLOCKED RUN. Disclosure is the point. The retired card showed 9/10 PASS with evidence-per-subcap failing, and that is the correct behaviour: the assessment ships with its weakness stated.
7.2 Corpus gate ceilings — the rule that keeps them alive
NEVER raise a ceiling to make a build pass. Every ceiling is a MEASUREMENT of the corpus as it is, so any regression past today's state fails the build. The only sanctioned movement is downward, after a defect class is actually fixed and re-measured.

Two corollaries learned the hard way. Ceilings must be per-client RATES, not fixed counts — a fixed count passes at 137 clients and fails at 138 on arithmetic alone, with no defect introduced. And a ceiling set from an acceptance target rather than a measurement fails every build on day one for defects the build did not introduce, which is how a gate ends up disabled wholesale.

8.1 The citation stack

V4 asks whether the output is ABOUT the bundle. It abstains when no embedding tier is available — an extra guard, never a fail-closed on a missing model.
8.2 Fail-closed
On any citation flag the surface fails closed: the deterministic fallback is served and an alert row is written. An AE never sees unvalidated content.

8.3 Grain resolution
For every “<label> at N/5” in produced prose: resolve the label to a served cell and require |rendered − served| ≤ 0.05. Round ONCE — rounding to 2dp and then to 1dp is not the same function as rounding once, and .x5 ties diverge between the two paths.
8.4 The identity gate — blocking, per figure
The retired system had no identity gate, and the consequence was visible on one client across FIVE surfaces at once: an Overview trajectory carrying another institution's assets, regulator and footprint; a thought-leadership panel quoting that institution's conference talk; a ceiling drilldown citing its annual report; a focus area whose source document was its client profile; and an evidence-age row whose source domain was its website. One root cause, five surfaces, and every instance catchable by one rule.
For EVERY figure, quote, document and source domain, assert:

  1  LEGAL NAME matches this entity (resolve suffixes; trading vs legal name)
  2  REGULATOR matches this entity's own
  3  FOOTPRINT / jurisdictions are consistent with this entity
  4  SOURCE DOMAIN belongs to this entity or to a known neutral registry
  5  ORDER OF MAGNITUDE agrees with any other figure for the same metric
     already in the pack — two figures for one metric differing by more than
     25% are a CONTRADICTION to resolve, not two data points to render

Any failure → quarantine the field, emit quarantine_reason, escalate.
Never render a partial identity.

The source domain is the cheapest identity check in the system and it catches the most. Run it on every item, at registration.

8.5 Cross-surface reconciliation
The same metric appearing on two surfaces must agree or one must be quarantined. This is a gate, not a review step, because the client reads both surfaces on the same screen.
8.6 Derived values must be computed
A derived value is either computed from real inputs or it is null. It is never a sentinel, never NaN, and a STATUS derived from it must follow from the computation.

The retired evidence-age tracker rendered “NaN mo” in every age cell while the status beside it read FRESH — a status asserted over an uncomputable age. The rule: if the input date is absent or unparseable, age is null, the band is UNVERIFIED, and the status is UNDATED. Every one of those three follows from the one before.
8.7 Thresholds are enforced or they are not thresholds
The retired cohort-patterns surface displayed a 50% row under a header declaring a ≥60% threshold. Either enforce it, or label the exception explicitly as BELOW_THRESHOLD. A stated threshold that does not hold teaches the reader to distrust every other number on the page.

Each rendered surface carries data-source="producer" | "parsed" | "empty". A surface that cannot say where its content came from cannot be audited from the outside, and a blank one is indistinguishable from a broken one.

10.5 Presentation guarantees the payload must satisfy
ORDER IS MEANING. A list renders in the order sent. Findings are ranked, phases sequenced, events chronological. Never rely on the client to sort.
IDS ARE THE JOINS. subcap_id, e_id, rec_id and ic_id are what wire a card to its drilldown. An unresolvable id is a dead control.
NO MARKDOWN IN A FIELD THAT RENDERS AS TEXT. Only fields explicitly typed as markdown go through a stripper; everything else renders literally, so a stray “### ” reaches the AE verbatim. 127 clients shipped exactly that.
TERMINAL PUNCTUATION on every prose field. 452 bodies across 136 clients shipped without it.
COUNTS ARE COMPUTED, NOT ASSERTED. Where a surface declares its grounding (“on the 3 items above”), that number is len(e_ids).
DENOMINATORS ARE RENDERED. A percentage without its base is not information — “96%” needs “of 761 cells carrying ≥1 linked item”.
11. Idempotency, concurrency, versioning
Concern
Rule
Re-registering a source
idempotent by content hash; returns the existing id with deduped=true
Resubmitting a page
supersedes the previous row for (run, page). No merge, no accumulation.
Re-promoting a run
idempotent — a promoted run promotes to the same state. Not an error.
Two sessions, one run
the claim lease prevents it. A lease expires so a dead session cannot block a run permanently.
Two runs, one entity
both persist. Promotion swaps which is ACTIVE; the prior run stays queryable for longitudinal surfaces.
Catalogue version bump
every id resolution is pinned to the run's ccg_catalog_version. Renamed cells resolve through the alias bridge; nothing silently vanishes.
Producer version
stamped on every serving row, so output can be attributed to the producer that made it and a regression can be bisected.

13. Session continuity
This section exists so a session that starts cold — with no memory of any prior conversation — can establish exactly where things stand and lose nothing.
13.1 Resuming: the first four calls, in order
get_run_progress(run_id) — per-page status, and what is blocking. This replaces guessing from verdicts.
get_page_contract(page) for each page still to do — read the shape rather than recalling it.
get_report_bundle(run_id) — the input, including source_cell on every score so grain can be asserted.
get_client_state(display_id) — what is currently SERVED, which is the diff target if this is a rerun.

13.3 The invariants, in one place
If a future change makes any of these false, it is a breaking change to this specification and not a refactor.
The app never calls a model at request time.
All content writes go through the MCP.
The API reads serving tables only.
Promotion is atomic across all six pages.
The agent creates only five id classes; everything else is read or requested.
Evidence ids are recognised by ONE pattern, in one module.
ERS is server-computed and bounded 1.0–5.0.
A quoted figure and its named cell are the same cell, within 0.05.
Every figure passes the identity gate before it renders.
A derived value is computed or null — never a sentinel.
Internal rungs are marked in the payload, not filtered in the frontend.
A corpus ceiling only ever moves down.

13.5 What this specification deliberately does not decide
The transport. JSON-RPC or REST are both acceptable; the exchange contracts in §4.1 are the same either way.
The hosting shape. Nothing here depends on where the MCP server runs.
The prompt text. That is the Surface Design Specification's job — this document governs the envelope, not the content.
Retention. How long superseded runs and verdicts are kept is an operational policy, not a contract.
Everything else in this document is a contract. Where the two specifications touch — a section name, an id format, a validation rule — this one is authoritative for the envelope and the Surface Design Specification is authoritative for what goes inside it.
