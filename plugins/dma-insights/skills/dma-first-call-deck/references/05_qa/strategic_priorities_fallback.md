# Strategic Priorities — Fallback Chain

> **Used by:** `scripts/03_editing/slide6_editor.py` (Slide 6 — Organizational Profile, shapes Sh11/12, Sh14/15, Sh17/18 — the 3 Strategic Priorities block).
>
> **When to apply:** When the agent cannot extract 3 distinct named strategic priorities from the client research report's structured fields. This fallback chain tells the agent how to complete Slide 6 without fabricating claims that could be challenged on a live sales call.

## Core principle

**Never fabricate a priority.** A visible `[DATA NEEDED: strategic priority N]` flag is preferable to a plausible-sounding but ungrounded claim. The sales rep can fill a flagged gap verbally on the call; they cannot retract a fabricated strategy once it's on a slide.

## The 3-level chain (fail-fast, stop at first success)

### LEVEL 1 — Research report extraction

Parse `client_research_report.pdf` / `.md` / `.docx` for sections titled (case-insensitive):

- "Strategic Priorities"
- "Strategic Objectives"
- "Strategic Initiatives"
- "Corporate Strategy"
- "Vision & Priorities"
- "5-Year Plan" / "3-Year Plan" / "Multi-Year Plan"
- "Key Initiatives"
- "Investment Priorities"
- "Growth Strategy" / "Growth Pillars"
- "Executive Summary" (sub-scan for bulleted priorities)

**Extraction rules:**
- Each priority must have a distinct **2–4 word title** (title case)
- Each priority must have **≥1 supporting fact or metric** (CAGR, $ invested, named initiative, board-approved objective)
- Dedupe near-duplicates (e.g., "Digital Transformation" and "Digital Strategy" → keep one, combine facts)

**Decision:**
- If **≥3 explicit named priorities** found → USE them (stop here)
- If **1–2 found** → hold them; proceed to Level 2 to fill remaining slots
- If **0 found** → proceed to Level 2

### LEVEL 2 — Web search fallback

Cap at **3 web searches** to stay within the batch tool-call budget. Log each search + source to the research audit trail (`research_audit/slide6_priorities.json`).

**Query sequence (run in order, stop early when 3 priorities reached):**

```
Q1: "{client_name}" strategic plan site:{client_primary_domain}
    OR linkedin.com/company/{client_linkedin_slug}

Q2: "{client_name}" annual report strategic objectives {latest_fiscal_year}

Q3: "{client_name}" CEO letter shareholders
    OR "{client_name}" investor day presentation
    OR "{client_name}" board of directors strategic priorities
```

**Source ranking (prefer earlier sources):**

1. **Client's own site** — `/about`, `/strategy`, `/investors`, `/press`, `/news`
2. **Annual report PDF** — SEC EDGAR (public companies), NCUA 5300 Call Reports (credit unions), state insurance department filings (carriers)
3. **Executive thought leadership** — CEO/CFO LinkedIn posts (verified profile only), executive interviews in trade press
4. **Trade press** — American Banker, CUToday, CU Times (credit unions), AM Best (insurance), ThinkAdvisor (wealth/RIA)
5. **Analyst reports** — S&P Capital IQ, SNL, Morningstar (only if directly reachable via search)

**Blocked sources (do NOT cite):**
- Glassdoor, Indeed reviews (not authoritative for strategy)
- Reddit / forums (unverified)
- Third-party marketing content (press releases generated by vendors)
- Archive.org snapshots older than 24 months (likely stale)

**Extraction per priority:**
- Name: 2–4 word title case
- Description: 1 sentence, ≤95 chars, with **at least one quantified fact or named initiative**
- Citation: URL + publication date (stored in audit trail, not on slide)

**Decision:**
- If **3 priorities** now available (Level 1 + Level 2 combined) → USE them (stop)
- If **<3** still → proceed to Level 3

### LEVEL 3 — Graceful degradation

For each unfilled slot, populate:

```
Sh{name_shape}: "[DATA NEEDED: strategic priority {i}]"
Sh{desc_shape}: "[DATA NEEDED: priority {i} description — research gap flagged]"
```

Log to `research_audit/slide6_priorities.json`:

```json
{
  "slot": "Sh11",
  "priority_number": 1,
  "status": "DATA_NEEDED",
  "level_1_attempted": true,
  "level_1_result": "no structured priorities section in report",
  "level_2_attempted": true,
  "level_2_queries": ["...", "...", "..."],
  "level_2_result": "only 1 distinct priority extracted from 7 sources",
  "recommendation": "sales rep fills verbally OR request deeper research before send"
}
```

## Quality guardrails

- **NEVER merge two client-mentioned priorities into one** to pad a missing slot. If the report mentions "Organic Growth" and "M&A" as distinct priorities, they stay distinct.
- **NEVER copy a competitor's strategy to fill a gap.** Even if the client is a fast-follower, the Slide 6 Strategic Priorities block must reflect what THIS client has stated.
- **NEVER describe a priority using our (Zennify's) solution language.** "Data Modernization" is a Zennify solution; "Unified Data Strategy" or "Member 360 Program" are the kinds of phrases a client would use to describe their own priority.
- **Timeframe sensitivity:** Priorities older than 24 months from the most recent annual report are candidates for update via Level 2 search. Flag in audit trail if a priority is being used but its source is >24 months old.

## Example — sourced correctly

```
Priority 1 name:  "Digital Member Experience"
Description:      "$12M investment over 3 years to modernize the mobile
                   app, online account opening, and agent desktop."
Source:           STCU 2025 Annual Report, p.14 (annual_report_2025.pdf)
Status:           VERIFIED (Level 1 — report)
```

## Example — graceful degradation

```
Priority 3 name:  "[DATA NEEDED: strategic priority 3]"
Description:      "[DATA NEEDED: priority 3 description — research gap flagged]"
Source:           None
Status:           DATA_NEEDED (Level 3 — exhausted report + 3 web searches)
Recommendation:   Account team confirms verbally on call OR triggers
                  a deeper research pass before client delivery.
```

## Verification command

After `slide6_editor.py` runs:

```bash
grep -E '\[Priority [0-9] name\]|\[One-line description' unpacked/ppt/slides/slide6.xml
```

Expected: **ZERO matches** (either priorities are populated, or `[DATA NEEDED: ...]` flags are in place — the raw template placeholders should not survive).

Additionally, audit the run:

```bash
cat research_audit/slide6_priorities.json | jq '.[].status'
```

Expected: all statuses are `VERIFIED` or `DATA_NEEDED` — never `FABRICATED` or missing.
