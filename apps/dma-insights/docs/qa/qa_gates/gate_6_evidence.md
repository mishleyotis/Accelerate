## Per-section verification

### §6.1 — `app/services/language_rewrite.py` (NEW pure-function rewriter)

The deterministic regex rewriter applies 24 rules across the 6
UI/UX brief categories:

| Rule | Phrase examples | Replacement |
|---|---|---|
| R1 — no hedging | `potentially`, `may be some`, `it seems`, `appears to` | drop / `evidence shows` / `is` |
| R2 — opportunity framing | `pain point`, `weakness`, `failure`, `weaken`, `deficient`, `lacking`, `poor`, `lags` | `area of focus` / `opportunity` / `gap` / `narrow` / `below benchmark` / `missing` / `limited` / `trails` |
| R3 — word economy | `a number of`, `significantly`, `significant`, `various` | `several` / `notably` / `material` / `multiple` |
| R4 — no jargon | `API error`, `HTTP 500`, `JWT expired`, `stack trace` | `integration error` / `service error (code 500)` / `session expired` / `error log` |
| R5 — no apologies | `unfortunately`, `apologies`, `oops`, `sorry` | dropped |
| R6 — active voice | `This report was generated by X` | `X generated this report` |

**Anchor preservation contract** — 7 anchor patterns (evidence IDs,
subcap IDs, issue/cap IDs, monetary values, percentages, score
notation, catalogue versions). Any rewrite that drops an anchor is
rejected by the post-validator; the wrapper serves the original
text.

### §6.2 — `app/services/narrative_polish.py` (NEW cache wrapper)

Sits on top of `language_rewrite.rewrite_text` and the existing
`vertex_synthesis_cache` infrastructure:

- New synthesis surface: `language_rewrite` with 7-day TTL
- Cache key: source content hash (so source UPSERT busts the cache
  automatically; matches the Batch 2 selective re-ingest contract)
- Best-effort: any cache / DB error falls back to source text
- Below 20-character source: skip the rewrite + cache entirely
  (overhead exceeds gain)
- Caches both `applied` rewrites AND `no_change_needed` results so
  the second read is a single SELECT regardless of source content
