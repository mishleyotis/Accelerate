00System architecture

The DMA Visualizer operates across two ingest phases: Phase 0 (DRIVE_PARSE) where Google Drive documents are crawled, classified, and parsed into structured assessment records; and Phase 1 (PROJECT_API) where pre-structured JSON payloads (app_payload_v1.json) are ingested via authenticated API. Both phases produce first-class entity records in the same schema.

Database engine: PostgreSQL 16 (primary) · Redis 7 (cache + SSE pub/sub) · Node.js 20 API server · Google Cloud Run (serverless) · Cloud Scheduler (scan jobs) · Vertex AI Gemini Flash + Pro (intelligence surfaces)

01Auth & JWT schema

Google OAuth 2.0 → server-side JWT exchange. JWT stored in httpOnly cookie (no localStorage). Role is embedded in JWT payload. Three roles: AE (read-only, no Analyst views), ANALYST (full internal view), ADMIN (user + import management).

JWT payload structure

{
  "sub": "google_oauth_sub_id",
  "email": "mishley@zennify.com",
  "name": "Mishley Otiende",
  "role": "ANALYST",            // AE | ANALYST | ADMIN
  "user_id": "uuid-...",
  "iat": 1716115200,
  "exp": 1716144000,            // 8h default session
  "iss": "dma-visualizer-api"

Security note: JWT stored as httpOnly, SameSite=Strict, Secure cookie. Never in localStorage. Token refresh occurs silently at ≥7h mark. Expired tokens redirect to /login with toast: "Your session has expired."

18Report parsing & storage · Phase 1 score streaming

DMA deliverables vary enormously in structure: a Client Profile Research Report has a company overview, tech landscape, leadership profiles, and regulatory signals; an Assessment Report has 4–6 paragraph pillar deep dives with evidence citations, scoring rationale, peer benchmarks, and transformation roadmap sections. A flat parse into runs and subcap_scores would lose all document-level structure, making the visualizer unable to surface "which paragraph in which report produced this score." This section introduces the document storage and lineage model that preserves that structure, alongside the real-time streaming tables that power Phase 1 Claude project execution.

3. subcap_scores.ccg_subcap_id → ccg_subcaps: inherits maturity descriptors, L3 platform context, offering gap baseline
4. SSE gateway listens to Redis pub/sub → emits batch_complete event to frontend on each sub-batch gate

6. Technographic validation → INSERT TECHNOGRAPHIC_VALIDATED event, update offering_gaps_identified
