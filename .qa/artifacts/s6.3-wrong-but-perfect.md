# §6.3 — The conclusion that is internally consistent, fully cited, correctly tiered, challenge-passing, and wrong

Every leg below was **measured**, not reasoned. The claim traced is deliberately ordinary:

> *"Institution X has deployed [Platform] across its servicing estate"* — supporting a
> Competing band on the servicing cells and a **hot** platform-fit card recommending the
> adjacent module.

The fact underneath is true-but-misread: the vendor announced a *signed contract*. Presence,
not utilization.

## What actually stops it today

**Nothing in the application.** One control exists and it is upstream, in the research skill
that is **not shipped** (§1.3): v4.2's R5 + `URF-01..06` + the 7-dimension `counter_evidence`
challenge. The installed v2.3 has none of it — `grep -c 'URF-' plugins/dma-insights/skills/dma-research/` = 0.

## The shape of the failure

Every gate in the path checks an **internal relation**: does the id resolve, does the tile
match the card, does the arithmetic reconcile, does the prose avoid a known string. Not one
checks the **external relation** — does this evidence answer the question that was asked, and
does the score match what the evidence actually shows. That is precisely the judgement the
thirteen PR #2 defects were caught by, and it is the judgement the target architecture deletes.

**Two of the eight legs are one-line fixes and would break the chain:**
- Leg 4: change `r.get("readiness") or "green"` to use `READINESS_DEFAULT` (`"amber"`), which
  already exists at `platform_fit.py:119` with a comment saying exactly why.
- Leg 1: count distinct *origins* rather than distinct domains — the docstring already
  specifies the right rule.
